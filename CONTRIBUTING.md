# Contributing to GitHub Contribution Tracker

Thank you for your interest in contributing! This document provides guidelines for contributing to the project.

---

## Ways to Contribute

### 🐛 Report Bugs
Found a bug? Please open an issue with:
- Clear description of the problem
- Steps to reproduce
- Expected vs actual behavior
- Screenshots if helpful
- Browser/environment info

### 💡 Suggest Features
Have an idea? Open an issue with:
- Clear description of the feature
- Use case (why is this needed?)
- Proposed implementation (if you have ideas)

### 📖 Improve Documentation
- Fix typos or unclear explanations
- Add examples
- Translate to other languages
- Improve setup instructions

### 🔧 Submit Code
- Bug fixes
- New features
- Performance improvements
- Code cleanup

---

## Development Setup

### Prerequisites
- Google account (for testing in Google Sheets)
- GitHub account
- Basic JavaScript knowledge

### Getting Started
1. Fork the repository
2. Clone your fork locally
3. Create a test Google Sheet
4. Copy `Code.gs` into the script editor
5. Make your changes
6. Test thoroughly
7. Submit a pull request

### Testing Your Changes
1. Create a fresh Google Sheet
2. Paste your modified code
3. Run Setup Sheets
4. Configure with a test repository
5. Run Fetch Contributions
6. Verify all features work correctly

---

## Code Guidelines

### Style
- Use consistent indentation (2 spaces)
- Use meaningful variable names
- Add comments for complex logic
- Keep functions focused and small

### Documentation
- Update relevant docs if behavior changes
- Add JSDoc comments for new functions
- Include examples where helpful

### Commit Messages
Use clear, descriptive commit messages:
```
Good: "Add support for GitLab file categorization"
Good: "Fix bug where merge commits counted twice"
Bad:  "Fixed stuff"
Bad:  "Update"
```

### Pull Request Process
1. Create a feature branch from `main`
2. Make your changes
3. Test thoroughly
4. Update documentation if needed
5. Submit PR with clear description
6. Respond to review feedback

### Our Standards

- Focus on the project, not individuals

- Publishing others' private information
